# 阶段3 QLoRA第一轮实验计划

收尾更新（2026-10-11）：实验范围已结项，独立50条已获用户整体认可，可选候选接入、失败隔离和工程验证完成。见[结项报告](reports/stage3-closeout.md)和[候选工作台指南](stage3-candidate-workbench.md)。原1,500–3,000条人工核验规模与跨域目标尚未达到，以下计划和此前进展保留为历史，不解读为新结果。

日期：2026-10-11。执行进展：步骤1—4及步骤5的同配置模型对照已完成。810条两轮QLoRA选中第102步，90条严格/宽松联合F1为0.2527/0.5095，优于未微调基线0.1139/0.2425。独立人工评测、跨域验证、工作台接入尚未完成。[完整实验报告](reports/stage3-sft-full-comparison.md)及[开发记录](development/stage-03.md)已更新；[小试报告](reports/stage3-sft-baseline-and-smoke.md)保留历史结论。

目标是让本地4B模型稳定输出带原文证据的意见单元，减少遗漏、重复和格式错误。900条AI标注足以开始可行性与教师蒸馏实验，但不能替代原proposal要求的人工核验及独立评测，也不能预先承诺F1提升。

## 1. 固定数据和输出格式

- 按各包最终manifest、首波100版本表、本700最终清单读取900条，共12,744意见，不扫描所有历史输出；保留每条数据来源、标签版本、教师声明和哈希。
- 将原文作为输入，答案保留opinions中的target、aspect、sentiment、intent、scope、evidence、occurrence。统一字段和序列化顺序，不擅自修订语义标签。
- coverage/reason、review_questions、作者来源、模型身份保留在审计元数据中，不要求学生模型复述整套审核账本。证据、推测及条件限定仍在答案中保留；不能因带疑问就删除整条记录或仅删意见却把原文保留成假阴性。
- 统计完整输入+输出token长度及长文分布，冻结训练格式、标签表、非思考输出方式和提示模板。只监督assistant答案，屏蔽system/user标签。
- 自动检查输出schema、证据连续子串、数据集哈希及泄漏，不重新进行逐条语义审核。

完成标准：900条来源可追溯，格式转换无语义改写，所有未纳入训练的记录均有明确原因。

## 2. 划分与同底座基线

- 计划按重复组划分约810条训练、90条内部验证；按长度及教师来源兼顾分布，固定seed。正式数量以转换和长度检查结果为准，同一记录及其意见不得跨集合。
- 90条仅是AI标签验证集，用来检查拟合和选择checkpoint，指标应称教师标注一致性；不作为人工金标准或跨域泛化成绩。
- 先运行未微调的同一Qwen3.5-4B，在同一验证集、同一推理提示和生成预算下建立基线。若保留few-shot，只取训练集案例并预先固定；不能拿验证/测试答案写示例。
- 记录JSON有效率、原文证据有效率、意见抽取Precision/Recall/F1、匹配后的方面/情感/意图指标，以及单条延迟和峰值显存。提前定义一对一意见匹配规则，区分严格证据匹配与宽松边界匹配，避免重复意见刷分。

## 3. 小规模真实数据试训

复用`configs/models.json`固定的Qwen/Qwen3.5-4B revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，只加载文本部分，训练环境使用`.venv`。不用重新下载或改用新底座。

| 参数 | 首轮起点，须经真实样本探针确认 |
| --- | --- |
| 量化 | 4-bit NF4、double quant，BF16计算 |
| LoRA | 文本模型all-linear，rank 8、alpha 16、dropout 0.05 |
| batch | micro-batch 1，gradient accumulation 16 |
| 学习率 | 1e-4，warmup ratio 0.05 |
| 内存 | gradient checkpointing、训练时use_cache=false |
| 序列长度 | 先统计token，目标2048—4096；按真实长样本显存决定，不直接截断原文或JSON |
| 小试 | 训练分区抽32条，包含长/短样本，20—50个优化步 |

若完整样本超出可承受长度，单独处理或登记暂缓；不把截断目标当成有效监督。长文切块需保证对象上下文、跨段证据与输出归属，不在首轮静默切块。

已有阶段0证据：短合成样本50步训练及adapter重载通过；1024 padding、all-linear rank8探针峰值约7.52 GiB。它不能证明真实4096-token样本可训练，故只做必要的真实样本前后向、loss有限性、梯度与adapter保存重载测试。通过后按测得吞吐估计总时间，不沿用合成探针耗时。

## 4. 首轮完整训练

- 从固定底座新建adapter，不使用已对32条循环10遍的小试adapter作为初始化，避免这32条被额外拟合。
- 本轮执行前明确第二轮条件：第一轮末dev loss低于初始，且比第25步再下降至少1%。实测0.204409→0.190978（下降6.57%），因此继续第二轮；最终0.180556。最多两轮，按全部已训练checkpoint最低dev loss选择，最终第102步。未根据生成F1调整选择。
- 先跑1个epoch，固定每约25个优化步保存并验证dev loss；若验证改善再继续第2个epoch，不先做大网格搜索。完整90条生成对照集中在最终候选adapter执行一次，避免每个checkpoint重复耗时生成；中途loss不能替代最终生成指标。
- 约810条、有效batch16时每epoch约51个优化步，具体由可用条数与采样器决定。保留最佳adapter、最后checkpoint、优化器状态、随机种子和全量参数，支持恢复。
- 第一轮只验证是否产生实际增益；不同时换底座、改提示、改标签，让结果不可归因。
- 如出现loss不下降、验证退化或格式改善但抽取召回下降，分析后只改一个关键变量，再做必要复跑；不把训练loss下降等同于业务质量提高。

## 5. 对照、人工独立评测与工作台接入

2026-10-11执行进展：独立50条餐饮评论按短/中/长15/20/15冻结，两版共100条同配置生成、独立性及文件哈希复验已完成，成对审核页面可用。见[核验指南](stage3-independent-review.md)；人工审核待进行，不将成对判断作为完整意见金标准，不接入工作台默认推理。

- 同底座未微调版与QLoRA版在相同配置下对照，报告格式、证据、方面情感、遗漏/重复、耗时、显存的变化；明确哪些指标基于AI参考答案。
- 正式宣称真实质量提升前，另留至少50—100条未参与提示/训练调参的新样本做独立人工核验；优先先冻结ID和去重组，不向训练流程暴露答案。原20条人工试标已用于规则开发，不能冒充新的盲测集。
- 人工评测可安排在第一轮训练进行期间或之后，不作为启动冒烟实验的前置大工程。该小评测规模也不等于原proposal的完整数据目标已达成。
- 达到收益条件再接入工作台，保留原模型回退；领域外推留到另一领域数据上验证，不能由餐饮900条推断已泛化。

技术依据：[Qwen3.5-4B官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)、[PEFT量化训练指南](https://huggingface.co/docs/peft/main/developer_guides/quantization)。NF4及all-linear是候选技术方案；本项目具体配置以固定版本和本机实测为准。
