# 阶段3试标指南 v1

状态：待20条试标验证；不是最终冻结规范。对应 `stage3-pilot-v1`，意见格式 `opinion-annotation-v1`。沿用阶段0的标签与证据指南，新增以下人工操作约定；不改变 ASAP 官方标签。

## 先做什么

1. 填写标注者昵称，阅读整条原文，再检查右侧机器草稿。模型草稿可能漏标、错标，不能只看已有卡片。
2. 每条卡片确认原文证据、对象、方面、情感、意图、归属。需要时新增、删除、复制拆分、合并。
3. 确认没有遗漏或重复后，勾选完整阅读检查项，点击“保存完整核验并下一条”。拿不准就写备注，点击“暂无法判断并下一条”。
4. 中途休息先“保存草稿”。重新打开会优先定位第一条未完成记录；上一条/下一条也会保存当前修改为草稿。磁盘保存后才能关闭页面，输入时不会逐字自动落盘。

## 意见怎么划分

- 一条意见对应一个方面；同一句同时评价不同方面时，分别标注，允许共用证据。同方面、同对象、同态度的重复表述可以合并。
- 例（编写的教学示例，不是金标准）：`分量少，不过味道很好。` → 分量/负面/抱怨；口味/正面/称赞。
- 例（跨领域教学示例）：`导出排版挺好，就是每次要等半分钟，希望快一点。` → 导出排版/正面/称赞；导出速度/负面/请求改善。这一期实际样本仍为餐饮，不能硬用餐饮标签处理软件反馈。
- 背景、菜单介绍和无关行程不需要标成中性意见。与产品/服务方面直接相关、没有明显情绪的体验事实可标中性/一般陈述。
- 完全没有适用意见时删除全部卡片，并勾选“没有适用意见”；模型没提取出来不代表没有。

## 对象、归属与证据

- 对象填写具体菜品、设施、服务或功能，如“菠萝海鲜饭”“服务员态度”。不能把一道菜的好评扩大成所有菜品或整个餐厅的好评。
- 当前对象、其他对象/竞品、过去体验/旧版本、归属不确定分别选择。与当前评价形成比较的其他对象可以保留意见并标清归属；无关背景删除。
- 目标可以用上下文概括，如“当前餐厅的服务”；不得编造实体。没有办法确定对象时填写“无法确定”，写明原因，通常存为待讨论。
- 证据必须是原文连续片段，包含必要的否定、转折、指代上下文。不要改写标点，不要用省略号拼接两段。跨句需要引用时可包含中间原文。
- 通过左侧句段选择器新增；或将原文复制到卡片的证据框中缩短/扩展。重复短句会显示出现位置及邻近上下文，必须选择正确的一处。不需要手算字符位置。
- “引用匹配成功”只检查文字与位置，不证明结论正确。

## 标签边界

- 情感：正面、负面、中性、混合、无法判断。正负可以分别提取时优先拆分；同一方面无法拆开的矛盾态度才用混合。无法判断不是未提及。
- 意图：称赞、抱怨、请求改善、求助、一般陈述、无法判断。同一证据同时抱怨并明确请求改变时优先“请求改善”，避免为两个意图重复统计同一意见。
- 不看整条星级推断局部情感。界面不展示官方标签和星级；模型草稿明确标为机器建议。
- “不过/还行/真贴心”等不能脱离前后文判断。讽刺缺少足够依据时不要猜测，存为待讨论。可以确定信息本身无法判定时允许 unknown，但必须写原因。
- 餐饮方面沿用18类，并保留“食材选择与搭配”“制作方式”。未覆盖的方面选“未覆盖 / 待定”，备注建议含义，不自行创建新标签。
- 分量是量多少，食材搭配是选了什么材料；桌距拥挤是空间，停车位和指引是停车服务，公交/地铁可达性是交通便利。
- 上菜慢是上菜及时性；入口已经凉等温度体验不自动当作上菜慢。推荐不等于口味，两者需要各自证据，不凭“服务员推荐”判断作者推荐。

## 保存与后续用途

- 草稿：未完成，可以保留暂时无效的证据。待讨论：有未解决问题，必须写备注。已完整核验：你检查了整条评论，且结构/证据检查通过。
- 这20条含10条固定种子随机样本、10条既有难例，均来自 clean-train。用于试标和修订指南，不用于独立评测；之后需要按冻结规范复查。
- 所有保存都保留历史及标注者。完整核验仍属于单人试标，`training_ready=false`；不会自动写成训练数据或正式测试金标准。AI 测试使用独立合成样例，不修改这20条人工状态。
- 指南更新需要新版本并明确受影响记录。后续再冻结训练/开发/测试划分；本轮不开始正式训练。
- 原文、标注库、备份仅保存在本地 `data/annotations/stage3-pilot20/`，不进入 Git。页面可下载包含原文和全部修改历史的本地备份。
