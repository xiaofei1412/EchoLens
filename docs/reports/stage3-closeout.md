# 阶段3结项：QLoRA候选与本地工作台

日期：2026-10-11。结论：本轮授权的阶段3收尾完成，按**实验版本范围**结项，可进入阶段4规划。候选模型可选、原基线可回退；没有直接替换默认模型，也没有重新跑1,000条。阶段4尚未实施。

## 模型与质量证据

- 固定 Qwen/Qwen3.5-4B，revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`；810条训练、90条开发，均为AI来源标注。按事先约定完成两轮并依据开发loss选中第102步 adapter，详见[完整训练报告](stage3-sft-full-comparison.md)。
- 90条AI参考上，严格/宽松联合F1为0.1139/0.2425 → 0.2527/0.5095，字段合法率75.56% → 97.78%。这是教师一致性，不能写成人工准确率。
- 独立50条两版结果均冻结。用户在对话中确认“剩余样本都没有问题”，整批接受；实际保存的逐条表仍为3条，3条均偏好微调后，不把其余47条自动计为胜出，不填造金标准。页面另显示整批验收状态。
- 独立50条机械指标：JSON合法47/50 → 49/50，字段合法46/50 → 48/50，达到输出上限2 → 1，平均生成30.20 → 48.09秒。原文和两版预测哈希再次核验未变，未用这些样本修改提示、标签或参数。

## 本轮工程交付

- 工作台侧栏“选择分析版本”可创建或打开独立QLoRA候选数据版本。原始分析、主题和审核记录不被覆盖；候选使用固定提示、28方面标签、NF4和所选adapter，关闭思考、贪心生成。
- 候选统计使用实际抽取意见，不把原18方面分类器结果误称为微调成绩。同一方面按不同反馈计数，保留混合情感；过去体验和其他对象仍可查看，但不进入当前对象统计或主题聚合。
- 输入超过4,096 tokens、输出达到4,096 tokens上限、JSON/字段/引用失败、未知标签/情感、归属不确定、完全重复意见，整条转复核，保留原始输出；失败意见不进入机器统计、主题或可靠证据索引。有效空结果单独提示检查遗漏。人工修订单独留历史，报告可明确展示人工修订。
- 每条完成即原子保存；输入、源码、环境、配置和输出均校验哈希。重新运行跳过已完成结果；版本或内容不一致拒绝混用。运行异常保留已完成记录、标记失败并释放GPU任务锁。语义/结构失败不自动无限重试；可人工修订或保留失败。默认模型与旧结果始终可用。
- 新旧标签表隔离，核对阶段2 v2/v3提示与few-shot哈希仍与历史运行记录一致，避免接入新标签时改变旧模型行为。

没有强制制造真实OOM；记录边界续跑不等于GPU内核中断后的数值等价验证。3条探针没有主主题，不宣称本轮验证了新模型的大规模主题质量或命名效果。合成测试覆盖截断、无效JSON/引用/标签、重复、未知归属、缓存篡改和混合/过去体验等边界。

## 问题、修复与保留限制

- 初次测试1项失败：旧报告的非当前对象文案被改变；恢复旧版本文案，候选才使用新的归属描述。后续59项、最终62项通过。
- Streamlit旧进程缓存旧模块导致`opinion_counts`导入失败；重启本地服务解决，没有安装或升级依赖。
- 实际回退切换触发控件默认值与Session State并设警告；已有会话值时不再指定默认index，增加往返切换验证后62项再次通过。
- 结项脚本首次误把`results_at()`字典当作多值返回，报错；按真实接口分别读取分类与抽取后复验通过，不涉及模型重跑。
- Windows仍使用缺少`causal_conv1d`和`flash-linear-attention`优化内核的PyTorch回退，速度不是硬件上限。平均延迟增加是已知代价。
- 原proposal的1,500–3,000条新增人工核验数据没有达到，当前是900条AI标注＋50条独立成对核验；本结项不宣称原始全部质量目标达成。独立字段合法率96%仍低于99%目标；通过失败隔离使实验工作台可用，不把隔离后的分母包装成100%模型成功率。
- 跨域泛化、长文本完整召回、含蓄/讽刺、对象边界仍需后续独立验证。阶段4应依真实数据条件规划新领域/真实时间功能，不继续围绕已看过的50条调参。
