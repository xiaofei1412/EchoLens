# 阶段3：数据、基线与真实样本试训

日期：2026-10-11。数据来源为AI教师标注；以下不是人工金标准成绩。

## 数据冻结

- 900条、12,744意见，来自已确认的20/80/100/700最终版本；没有新增语义修改。
- 按教师来源与原文长度分层，seed=20261011，810训练/90内部验证；重复组交叉0。
- 完整输入和答案长度552—3,101 tokens，中位1,263、P95 2,191；最长答案2,028 tokens。全部在4,096预算内，没有删长文或截断JSON。
- 仅监督assistant答案。所有900条均通过字段、连续原文证据、来源哈希及prompt loss屏蔽检查。
- 验证集只用于内部AI参考一致性；原有独立测试数据未参与此次转换、提示或训练。数据、原文、权重及逐条生成输出只保存在Git忽略目录。

## 未微调基线

固定Qwen/Qwen3.5-4B revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，文本部分、NF4 double quant、BF16计算。无few-shot，关闭思考，greedy生成，每条最多4,096新tokens，90条全部计入。

| 指标 | 实际结果 |
| --- | --- |
| JSON及顶层opinions数组有效 | 82/90，91.11% |
| 所有意见字段及标签合法 | 68/90，75.56% |
| 字段合法且原文证据可定位 | 842/1,005，83.78% |
| 严格联合Precision / Recall / F1 | 0.1303 / 0.1011 / **0.1139** |
| 宽松联合Precision / Recall / F1 | 0.2776 / 0.2153 / **0.2425** |
| 精确证据匹配后的情感一致率 | 87.72%，仅228个匹配对 |
| 平均每条生成时间 | 36.93秒 |
| 90条生成时间合计 | 55.40分钟，不含加载 |
| 达到输出长度上限 | 4条，保留并计入失败/匹配统计 |
| PyTorch峰值已分配显存 | 3.39 GiB，不含桌面及非PyTorch占用 |

严格联合匹配要求证据起止位置、方面、情感同时一致；宽松仅将证据边界放宽为字符跨度IoU≥0.5。两者均采用最大一对一匹配，重复预测不能重复获取TP。对象名称、意图、归属不参与该联合F1；其精确字符串一致率另存JSON，仅供诊断，不等于完整语义正确率。

无法解析的整条输出计一个FP，且该条所有参考意见计入召回分母；它不是“恢复其中可能存在的意见后”计算的分数。因而1,005是计分预测数，不能理解为所有失败文本中实际写出的意见总数。“证据有效率”还要求字段合法，不是单独的子串命中率。

格式不稳、遗漏和证据边界差异均有提升空间；精确匹配子集的情感一致率不能代表全体意见情感准确率。不能将本分数与阶段1的方面分类F1直接比较，任务和计分单位不同。

## 真实样本试训

已完成：从810条训练分区按长度取32条，包含最短552和最长3,101 tokens，0条因长度排除。每条完整输入和答案监督，无padding扩长或目标截断。

配置：NF4 double quant，BF16 autocast，文本all-linear，rank8/alpha16/dropout0.05；micro-batch1、梯度累积16、20个优化步，32条循环10遍。AdamW学习率1e-4，betas=(0.9,0.999)，eps=1e-8，weight_decay=0.01，梯度裁剪1.0；5% warmup在本20步试验中为1步，其余学习率恒定。seed=20261011，gradient checkpointing非reentrant，use_cache=false。可训练参数16,232,448。

| 检查 | 实际结果 |
| --- | --- |
| 完成优化步 | 20/20，共320个micro-batch |
| 首轮32条平均训练loss | 0.30719（第1—2步均值） |
| 末轮32条平均训练loss | 0.07177（第19—20步均值） |
| 非有限loss/梯度、OOM | 均未发生 |
| PyTorch峰值已分配显存 | 14.817 GiB |
| 前后向及优化总时间 | 736.32秒，约12.27分钟 |
| adapter实际发生更新 | 通过 |
| 保存后重载所有adapter参数相等 | 通过 |
| 检查样本重载前后logits最大绝对差 | 0.0 |

训练loss按每条答案平均、每16条组成一步；长短两组交替，比较成对步均值才覆盖同一32条。这里只证明学习、显存和保存重载链路可用，不是90条验证成绩，也没有重新跑90条生成。保存了adapter、tokenizer、优化器状态和Torch随机状态；该小试脚本不提供中断后续训入口，完整训练时再实现checkpoint恢复。

显存余量很小，后续先保持本配置与单条batch，不扩大长度。按本次36.82秒/优化步粗估，810条一轮约51步的训练计算约31分钟；实际全量样本分布、验证loss、保存和系统负载会增加或改变耗时，最终以实跑为准。

下一步是从同一固定底座新建adapter，训练810条1个epoch，在中途/结束验证dev loss后决定是否需要第2轮。不要用重复拟合32条的本次adapter作正式训练起点。最终候选模型仅执行一次同配置90条生成，与上述基线比较；新的独立人工/跨域评测仍需后续安排。
