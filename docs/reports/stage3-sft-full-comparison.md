# 阶段3：810条完整QLoRA训练与基线对照

日期：2026-10-11。已完成2个epoch及90条最终生成对照，训练/评测退出码均为0。抽取一致性和格式均改善，生成速度下降；参考答案为AI教师标注，不是人工金标准。

## 训练与选择

固定使用`data/training/stage3-sft-v1`的810训练/90内部验证。底座为Qwen/Qwen3.5-4B，revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，只训练文本部分。新建adapter，没有从32条小试权重继续训练；数据、标签、提示和计分规则保持不变。

NF4 double quant、BF16 autocast，all-linear rank8/alpha16/dropout0.05；micro-batch1，累积16，最后10条按实际条数归一化。每轮810条各出现一次，无丢弃/截断。AdamW学习率1e-4，3步warmup后恒定，weight_decay0.01、梯度裁剪1.0，非reentrant gradient checkpointing。完整参数、依赖版本与源码哈希保存在聚合JSON和本地源码快照中。

训练前固定规则：第一轮末loss低于初始，且比第25步再下降至少1%，才继续第二轮。实测再下降6.57%，因此执行第二轮；最多两轮。最终按所有已训练checkpoint最低dev loss选择第102步，不依据生成F1挑checkpoint。

两轮共102个优化步、1,620条样本访问（810个不同训练记录各两次）。训练计算3,187.73秒（53.13分钟），五次完整验证共226.64秒（3.78分钟）；PyTorch峰值已分配显存14.8776 GiB，无OOM或非有限loss/梯度。上述计算时间不含首次失败尝试、加载、保存及最终自回归生成。验证loss按每条答案token平均，再对90条平均；下降不直接等于抽取F1改善。

本地最终adapter：`artifacts/stage-03/sft-full-v2/checkpoint-0102-29217c/adapter/`。第25、51、76、102步均保存adapter、tokenizer、优化器、随机状态和下批位置，逐文件哈希封存。实际检查了checkpoint25恢复材料，但未主动中断正常训练验证恢复数值等价。最终adapter已从磁盘加载，并与保存参数逐项精确相等。

严格/宽松F1绝对增加0.1389/0.2670，宽松召回由21.53%升至48.38%。格式和引用定位明显改善，仍不能说意见已经提全；严格与宽松结果差距提示证据边界仍需关注。两条输出触及长度上限，保留并计错，没有重试后择优或删除失败样本。

计分预测数1,165包括两条残缺JSON各计的一个FP；“证据可定位”还要求字段合法，不是语义正确率。严格/宽松联合F1均不要求对象名称、意图、归属同时正确。精确证据匹配子集上的方面/情感一致率为85.13%/92.31%（390个匹配对），与基线的228个匹配对不是同一子集，不能外推为全体意见准确率；详见JSON原始聚合结果。

平均延迟增加约38.8%。全体生成token由66,824降到61,508，说明更慢不能仅解释为输出更长；本轮固定带adapter的推理路径，没有合并权重或更换内核来优化速度，也未做性能瓶颈归因。吞吐优化应作为独立实验，避免与本次训练收益混杂。

机械验收通过：两组各90个相同唯一ID、相同数据/模型/指标哈希及依赖版本；从原始预测重新计分与报告完全一致。1,640个原始来源文件和冻结包文件哈希未变；每轮均51步/810条，最佳与最后checkpoint哈希通过，adapter重载参数精确一致。

建议保留此候选模型，不直接增加第三轮。下一步优先独立人工核验新样本，重点看遗漏、证据边界和跨对象归属；输出上限问题与推理性能可单独验证。本轮没有接入工作台或替换现有模型。

## 运行问题与修复

最初`sft-full-v1`运行在初始验证后出现明显延迟：首个训练步128.5秒。Windows GPU进程计数器显示共享内存约14.86 GiB、专用内存约15.20 GiB，而PyTorch已分配峰值仅11.39 GiB；只看allocated会低估系统内存压力。主动停止并保留原日志，后续生成因训练未完成而自动阻止。

改为每条变长训练/验证样本完成后释放空闲CUDA缓存，另存`sft-full-v2`从底座重跑，未改训练语义。新进程采样共享占用约82 MiB，初始验证117.6→45.2秒，首步128.5→28.7秒；初始验证loss和首步训练loss与v1一致。其余步骤稳定完成，未为了省显存截断原文。

环境仍缺少可选causal_conv1d与flash-linear-attention优化内核，使用Transformers的PyTorch回退实现；没有升级依赖。训练/生成吞吐是本机本环境结果，不是该显卡的理论性能。
