# 标签与证据指南 v0.1

状态：基于阶段 0 探索的草案，待用户审核。ASAP 官方标签与新增意见单元标注分开保存。

## 标注单位

一条反馈可以包含多个意见单元，每个单元关联一个产品/服务方面、一种情感、一种意图及原文证据。先锁定说的是哪家店/哪次体验，再判断态度；其他实体的评价不归到当前对象。

18 个方面沿用 ASAP；中文名称是阅读辅助，官方 ID 不变。无法归入现有方面的内容进入待扩展队列，不硬套标签。未知与未提及分别表达不确定性和原文缺席。

## 边界规则

- 正面、负面、中性针对证据所表达的态度，而不是星级。混合情感优先拆成独立可证据化单元；不能拆分时才标 mixed。
- “一般”“还行”结合语境；“没有觉得难吃”与“很好吃”强度不同，探针的简化例子不能替代正式指南。
- 排队等位归 Service#Queue；点餐后等上菜归 Service#Timely；冷淡、礼貌、处理争议等归 Service#Hospitality。
- 便宜/贵对应 Price#Level；划不划算对应 Price#Cost_effective；优惠券/折扣对应 Price#Discount。单独金额不推断价格态度。
- 菜品多不等于分量大；份量与种类区分。卫生、装修、空间、噪音分别处理。
- “希望/能不能/建议”包含明确改变请求时标 improvement_request；单纯抱怨只标 complaint。分析者提出的改进方案另存，不写成用户需求。
- 求助是用户需要信息或操作帮助；反讽性问句不能仅凭问号当作求助。
- 引述他人观点、当前作者评价、过去与现在分开；涉及食品安全、动机等只记录作者声称，不把猜测升级成事实。
- 官方标签可能聚合多个菜品或遗漏方面。保持 original_label，新增 reviewed_label 与理由；没有人工复核不作为纠正真值。
- 菜系百科、活动介绍等可能不是针对餐厅的评价。先判断任务相关性；地理区域的交通描述不能直接当门店交通评价。

## 证据契约

阶段 0 输出 `opinions` 数组；每项包含 `aspect`、`sentiment`、`intent`、`evidence`。evidence 必须是非空原文连续片段，保留否定词和必要上下文。不接受生成的解释作为引用。

当前验证器检查字段、枚举及原文包含关系，不验证语义蕴含。重复短句的唯一位置、目标实体和证据是否充分需要复核；后续定位采用原文 Unicode 字符零起始、左闭右开偏移，避免清洗后坐标漂移。

## 数据分离

探索仅使用训练集。新增标注按指南试标后冻结 dev/test，之后不能用于改提示、训练或阈值。AI 初读、模型建议、人工核验、人工争议分别标识。星级分层探索集不代表真实总体分布。

当前没有已完成的人工金标准，也没有声称双人一致性。人工审核修改本指南时提升版本，并在对应 docs/development/stage-NN.md 记录变更与需要重标的样本范围。
