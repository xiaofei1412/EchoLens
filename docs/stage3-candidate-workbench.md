# 使用阶段3候选模型

在工作台侧栏选中数据集，展开“选择分析版本”，点击“创建 / 打开 QLoRA候选版本”。这会创建独立版本，保留原结果及审核；在概览点击“开始 / 继续本地分析”才会启动后台任务。已有候选版本可直接打开，点击“返回原分析版本”即可回退。

本机可直接查看“阶段3 · 3条接入验证 · QLoRA候选”：3条开发样本已完成，供确认功能和证据展示。它不是新的质量测试。没有自动重跑原1,000条；默认页面仍展示阶段2 v3。

候选固定第102步adapter；候选概览基于抽取意见、覆盖28方面并保留混合情感。旧18方面分类器仅作独立参考。过去体验和其他对象不计入当前对象统计，失败记录保留在分母和复核提示中。没有真实日期时不显示趋势。

## 失败与续跑

- 程序中断后使用相同入口继续：已完成记录保留，只生成尚未完成的记录。配置、输入或运行代码改变时拒绝混用；需要开发者创建新的版本，不能删除旧哈希强行续跑。
- 格式/引用错误、输出触顶、未知方面/情感/归属、完全重复意见：整条进入复核，不作为可靠机器证据。原始输出仍可查看。
- 输入过长直接拒绝，不静默截断；本阶段没有加入长文自动分块。空结果提示检查遗漏。
- “失败但已完成”的记录不会每次续跑自动再生成。可以在复核页人工修改并单独保存，或保留失败和原始输出；运行层故障恢复只续未完成项。
- 候选报告的机器统计不被人工审核覆盖；人工修订在证据索引中单独显示。未知模型判断不自动等于人工审核通过。

## 本机命令

```powershell
$env:PYTHONUTF8='1'
# 工作台：.venv-stage1；候选GPU子进程自动使用.venv
.\.venv-stage1\Scripts\python.exe -m streamlit run app/streamlit_app.py --server.address 127.0.0.1 --server.port 8501
# 已创建的三条验证版本（重复执行不会重复候选生成）
.\.venv-stage1\Scripts\python.exe scripts/run_workbench_job.py --dataset stage3-integration3-qlora-v1
# 汇总核验，不重新生成独立50条
.\.venv-stage1\Scripts\python.exe scripts/report_stage3_closeout.py
```

依赖和权重沿用本机已有环境；本轮不安装新包。候选配置在`configs/stage3-candidate.json`，运行版本在各数据目录`candidate-run.json`。原文、输出、审核、权重和日志不提交Git。独立50条已整体获得用户认可，页面逐条表仍按实际3条显示；整批接受并不生成47份表或人工金标准。
