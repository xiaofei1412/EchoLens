# 回声工作台：本地使用说明

## 启动

```powershell
$env:PYTHONUTF8='1'
.\.venv-stage1\Scripts\python.exe -m streamlit run app/streamlit_app.py --server.port 8501
```

浏览器打开 http://127.0.0.1:8501 。只绑定本机地址，不发布外网。沿用阶段 1 独立环境；阶段 2 增加依赖见 requirements-stage2.txt，完整已安装版本见 requirements-stage2-lock.txt。

首次重建演示数据时，先完成阶段 1，然后运行：

```powershell
.\.venv-stage1\Scripts\python.exe -m pip install -r requirements-stage2-lock.txt
.\.venv-stage1\Scripts\python.exe scripts/prepare_stage2.py
.\.venv-stage1\Scripts\python.exe scripts/run_workbench_job.py --dataset asap-demo-1000
.\.venv-stage1\Scripts\python.exe scripts/prepare_stage2_revision.py
.\.venv-stage1\Scripts\python.exe scripts/run_workbench_job.py --dataset asap-demo-1000-v2
.\.venv-stage1\Scripts\python.exe scripts/verify_stage2_revision.py
```

默认打开「ASAP · 1,000 条 · 阶段2修订 v2」，原 v1 保留在侧栏供对照。修订运行使用相同原文和相同分类器预测。已有的 v1 聚合报告和原文报告不需要重写。

工作台 GPU 模型依次运行，不同时常驻。v2 按上下文窗口落盘，全部窗口生成后汇总为记录；中断续跑会复用已保存窗口；原始失败也算已处理，保留供复核，不自动无限重试。变更模型、提示词、配置或数据快照时拒绝接续旧实验。

第三轮 v3 在完整 v2 上增加逐片段上下文校对，并保留 v1/v2。已有 v2 后运行：

```powershell
.\.venv-stage1\Scripts\python.exe scripts/prepare_stage2_v3.py
.\.venv-stage1\Scripts\python.exe scripts/analyze_stage2.py --dataset asap-demo-1000-v3 --pilot
.\.venv-stage1\Scripts\python.exe scripts/run_workbench_job.py --dataset asap-demo-1000-v3
.\.venv-stage1\Scripts\python.exe scripts/verify_stage2_v3.py
```

v3 完成主题后默认展示第三轮数据；运行中仍可在侧栏选择它查看进度。校对候选逐条缓存，恢复任务不会重新生成已保存输出；源 v2 抽取的合并 SHA 也被固定。v3 不是新的微调模型：它复用 Qwen3.5-4B，以完整评论校对候选，不向模型显示旧方面/情感。未覆盖转折分句仅用于补充候选，并非看到转折词就自动判负面。

第三轮主主题至少涉及 10 条不同反馈，按反馈数排序，方面内采用 average-link 距离 0.35；距离阈值限制合并平均距离，不等于任意两条都相似。低频意见可在未成组列表回查，低频不等于不重要。新上传数据仍按已实现的 v2 原始抽取流程运行；第三轮当前是基于完整 v2 演示数据的可追溯修订流程。

每条反馈可展开「第二遍机器校对依据与剔除项」，查看机器为什么保留/剔除候选，以及有无证据边界规则修正。这些操作均不计入人工审核；模型可能错误剔除有效意见，应与 v2 对照。v3 引用由程序从已有原文位置复制，引用精确不能当作模型语义正确的证明。

## 建议审核顺序

1. **概览**：查看记录数量、有效抽取数量、方面统计和质量报告。统计来自分类器预测，分母是已分类反馈记录；一条评论可能提及多个方面。
2. **反馈与证据**：可直接搜索记录编号（例如 5365、38689），也可搜索原文；方面/情感筛选仍依据原 18 方面分类器。原文黄色区域是被模型选中的连续片段；右边查看标签、对象、意图以及失败原因；对象待定不表示整家餐厅。可导出当前筛选范围的报告。
3. **主题候选**：按「主题方面」筛选，再查看代表片段、边界片段及完整原文。边界片段不是负面评价，也不是已验证反例。机器建议的主题名称不自动成为正式标签。重命名、合并、拆分会追加新版本，旧版保留。
4. **复核与导出**：优先处理抽取失败、部分意见失败、方面或对象待定，再抽查通过项。v2 表格可修改方面、情感（-1 负面、0 中性、1 正面）、意图、对象、归属和原文字符位置。位置从 0 开始、结束位置不包含在内；不改位置就保留精确引用。可展开原文片段表辅助定位，填写审核者并保存。
5. **导入数据**：上传 UTF-8 CSV/JSONL，选择原文、ID、可选 1–5 星评分字段。空文本会排除并报告行号；已有分析的数据新增记录需使用新版本，避免覆盖历史结果。新数据可在概览中启动后台分析。

## 通过、失败与人工审核

v2 输出包含方面、情感、意图、评价对象和连续原文引用。短窗口保留前后文，程序逐条校验并映射到原文位置，合并同对象、同方面、同情感和同意图的相邻重复意见。

- **全部通过字段与定位检查**：没有解析或字段错误，没有对象定位警示。仍需检查语义。
- **有可用抽取 / 部分意见待复核**：部分意见可定位，另有条目失败、对象不匹配或超过提示的每窗口 6 条上限。保留可定位的条目与失败原因，不伪称整条通过。
- **抽取失败**：没有可保留意见且存在校验错误。原始输出留存供复核；不自动填充答案。
- **引用恢复**：模型仅增加空白或用省略号跳过原文时，只有每个片段能唯一、按顺序定位才恢复为包含中间内容的连续原文，页面明确提示。改写、顺序错乱或多处匹配不接受。恢复后原文存在仍不证明语义正确。

引用中的对象不匹配时不自动猜测，显示待定；明显涉及比较对象的意见标记归属待核验、排除机器聚类。这是有限的提示规则，不是完整指代消解。超量保留策略会增加意见数，不能与 v1 的「每条最多 3 项、整条拒绝」直接比较为准确率提升。
“引用可定位”仅证明文本存在，不证明标签正确或引用足以支持结论。例如“卷心菜不适合菠萝饭”仍可能被模型误标成“分量”。这些语义错误需要你核验。

低把握使用未校准的分类最大概率阈值 0.65；模型分歧只比较已经抽取的同方面情感，不把未抽取的其他方面自动判为冲突；随机抽查由稳定记录 ID 抽取约 5%。都只是复核入口，不是准确率。

人工审核不重算机器主题或统计；需要调整主题时使用主题页的编辑入口。人工审核保存独立事件：确认可用、已修正、不适用/拒绝。机器结果不被改写；报告中的证据优先采用最新审核意见，拒绝项不输出证据，方面统计仍明确使用机器预测。审核和主题变更另行导出 JSONL。合成验收数据的操作标记为 automated_fixture，不计入真实人工金标准。

## 修订版人工判断边界

- **评价对象**：引用中的具体菜品、设施或服务对象。相邻赞美承接同一道菜时合并并保留菜名；没有足够依据时留空，不扩大为所有菜或整家餐厅。
- **食材选择与搭配**：评价用了什么食材、配料组合是否合适；味道、软硬、油腻等通常属于口味。**制作方式**用于针对烹制做法本身的意见；卖相用于外观和摆盘。
- **分量**：店家提供的份量多少。点单数量、吃了多少、吃光都不能单独推出分量好坏；“正常”等描述也不能自动变成正面。
- **空间、装修、停车**：桌位拥挤和布局归空间，陈旧或风格归装修，车位及停车入口标识归停车服务。等位不等于等上菜。
- **情感和意图**：先检查有没有评价依据；年龄、金额、菜名本身不等于赞美。只有明确提出改变请求才标改进意图，不替用户补需求。
- **归属与证据**：保留否定、转折、比较和转述的必要上下文。别家餐厅的意见不算当前餐厅；无法确定就标待核验。引用中出现对象只是存在检查，不是归因正确的证明。

这些是阶段 2 复核使用的补充规则，不修改 ASAP 官方标签、不构成人工标注结果。当前输出只支持负面、中性、正面；遇到混合态度优先拆为分别有证据的意见，不能直接填写阶段 0 草案中尚未实现的 mixed。

## 主题与数据边界

v2 先按抽取模型预测的方面分组，再对 Qwen 语义向量做完整连接聚类（簇内最大余弦距离 0.30），每簇至少 3 条不同来源反馈；不满足条件的意见留在离群区。未知方面或归属待定也不强行成簇。代表片段优先选择不同反馈。方面本身仍可能预测错误；关键词和大模型只拟定候选名称。原 v1 的 PCA/HDBSCAN 结果保留供对照。原始聚类中心距离用于代表/边界排序，人工合并拆分后不伪称已重新聚类；边界片段不是已经确认的语义反例。

ASAP 没有真实时间、产品和用户标识，因此不启用趋势、不计算用户受影响比例。1,000 条来自去污染训练集，演示的是流程可用性，不是泛化测试成绩，也不是人工新增的意图/证据金标准。

本地数据、审核事件与分析结果位于 data/workbench/；日志和完整带原文报告位于 artifacts/stage-02/。它们都不进入 Git；公开只提交不含原文的聚合验收结果。

本轮新旧对照位于本地 `artifacts/stage-02/revision-comparison.html`，覆盖 5 条用户案例、27 条开发探针和另外固定的 32 条训练样本。它是待审核材料，不是人工金标准。完整修订报告为 `artifacts/stage-02/feedback-report-v2.md`。

第三轮完整对照为本地 `artifacts/stage-02/revision-v3-comparison.html`（32 条开发探针加 32 条额外样本），完整报告为 `artifacts/stage-02/feedback-report-v3.md`。全量产生 76 个主主题、6,769 个可定位意见；主题支持数达标不代表语义已经通过。已见的多方面丢失、引用不充分、规则误伤及主题边界误入，详见 `docs/reports/stage2-v3-review.md`；原 v2 对照页和报告继续保留。
